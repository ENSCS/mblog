# mBlog

เว็บบล็อกที่สร้างเองด้วย PHP + MySQL ล้วนๆ (ไม่ใช้ WordPress) กำลังพัฒนาแบบเริ่มจากส่วนเล็กๆ ก่อน ดูแผนงานทั้งหมดได้ที่ [PLANNING.md](PLANNING.md)

## ตอนนี้ทำอะไรได้แล้ว

ระบบเขียนบทความแบบ WYSIWYG พร้อม **ฐานข้อมูล MySQL เต็มระบบแล้ว**:

- เขียน/แก้ไข/อ่านบทความ ([editor.php](editor.php), [article.php](article.php), [articles.php](articles.php)) และ **หน้าเดี่ยว (Page)** เช่น เกี่ยวกับเรา/ติดต่อเรา/นโยบายความเป็นส่วนตัว ([page.php](page.php), [pages.php](pages.php)) — สลับประเภทได้ในตัวเขียนเดียวกัน ซึ่งเป็น WYSIWYG เทียบเท่า WP editor พื้นฐาน (จัดฟอร์แมตข้อความ, แทรก/จัดตำแหน่งรูปภาพ, ลิงก์ + auto-link, code block พร้อม syntax highlighting — รายละเอียดทั้งหมดดู [BUILT.md](BUILT.md))
- ระบบร่าง/เผยแพร่ (draft/published) แยกปุ่มชัดเจน พร้อมหน้ารายการร่าง ([drafts.php](drafts.php)) — **แก้ slug เองได้พร้อม 301 redirect อัตโนมัติ** กันลิงก์เก่าที่แชร์ไปแล้วใช้ไม่ได้
- **จัดการบทความแบบ WP** ([manage-articles.php](manage-articles.php)) — เลือกหลายแถว + bulk action, ค้นหา/กรองด้วยข้อความ/หมวดหมู่/แท็ก/ช่วงวันที่, แท็บทั้งหมด/เผยแพร่แล้ว/ร่าง/**ถังขยะ** (ลบ = ย้ายเข้าถังขยะ กู้คืนได้ ลบถาวรถึงจะหายจริง)
- หมวดหมู่ (ไม่บังคับเลือก, 1 บทความอยู่ได้หมวดเดียว) และ**แท็กแบบ freeform** (many-to-many, พิมพ์สร้างเองได้) พร้อมหน้ารวมบทความตามหมวดหมู่/แท็กที่อัปเดตอัตโนมัติ ([category.php](category.php), [tag.php](tag.php)) — หน้ารวมทั้ง 5 แบบ (บทความ/หน้า/หมวดหมู่/แท็ก/ร่าง) มี pagination + พรีวิวเนื้อหา + ยอดวิวในการ์ดครบ
- **นำเข้าบทความจาก Markdown อัตโนมัติ** — รับไฟล์สรุปหุ้นรายวันจากสคริปต์ภายนอกผ่าน API (ยืนยันตัวตนด้วย token) หรืออัปโหลดมือที่ [import-markdown.php](import-markdown.php) พร้อมแท็ก/เครดิตแหล่งที่มา/ภาพปกจาก YouTube ให้อัตโนมัติ
- **ค้นหาบทความสาธารณะ** ([search.php](search.php)) — ค้นทั้งชื่อเรื่อง/เนื้อหา/แท็ก
- เมนูเว็บปรับแต่งได้ รองรับเมนูย่อย — desktop เปิดด้วย hover แบบ WordPress, มือถือเป็น hamburger + accordion
- SEO พื้นฐานครบ: featured image, meta description (auto-generate จากเนื้อหา), Open Graph/Twitter Card, canonical tag, JSON-LD, [sitemap.php](sitemap.php), [robots.txt](robots.txt) — **ปรับ SEO เองต่อบทความได้ด้วย** (title/description/noindex แยกจากค่า auto-generate) ที่ [editor.php](editor.php)
- **ปักหมุดบทความ/หน้า** — เลือกให้ขึ้นก่อนใครใน [articles.php](articles.php)/[pages.php](pages.php) ได้ พร้อมจัดลำดับเอง จัดการรวมที่หน้าแยก [sticky-items.php](sticky-items.php) (ค้นหาแล้วปัก ไม่ต้องไล่หาทั้งรายการ)
- **ตั้งเวลาเผยแพร่ + วันหมดอายุ** — ตั้งบทความให้เผยแพร่ล่วงหน้าหรือหมดอายุอัตโนมัติได้ที่ [editor.php](editor.php) โดยไม่ต้องมี cron ฝั่งเซิร์ฟเวอร์
- หน้า error กลาง (404/500) + log ข้อผิดพลาด
- **Backup ทั้งเว็บ** (ฐานข้อมูลทุกตาราง + ไฟล์อัปโหลด ไม่ใช่แค่ไฟล์เหมือนเดิม) — กดปุ่ม "Backup ตอนนี้" ที่หน้าแอดมิน [backup.php](backup.php) ได้เลย มีลิสต์ backup เก่า ดาวน์โหลด/ลบทีละไฟล์ พร้อม retention อัตโนมัติ (`scripts/backup.php` รันผ่าน cron ได้เช่นกัน)
- **กำจัดไฟล์กำพร้า** ([orphan-files.php](orphan-files.php)) — สแกนหาไฟล์ใน `uploads/` ที่ไม่มีบทความ/sidebar/โลโก้เว็บอ้างอิงถึงแล้ว (เช่น รูปที่เคยฝังในเนื้อหาแล้วลบออกทีหลัง) ติ๊กเลือกแล้วลบได้เอง — ไม่มี auto-delete
- **ธีมเว็บสว่าง/มืดสลับได้** พร้อม**แบรนด์เว็บ** (โลโก้/favicon/สโลแกน) ตั้งค่าได้เองที่ [settings.php](settings.php) และ**ปรับแต่งชุดสีทั้งเว็บเองได้** (สีหลัก/ลิงก์/พื้นหลัง ทั้ง 2 ธีม) พร้อมพรีวิวสด export/import ที่ [theme-editor.php](theme-editor.php)
- **Sidebar** — แบนเนอร์/ประกาศ/ป้ายลิงก์ข้างเนื้อหา จัดการได้เต็มรูปแบบที่ [sidebar-items.php](sidebar-items.php) เปิด/ปิดได้ทั้งระดับเว็บและบังคับต่อบทความ/หน้า — เลือกได้ 2 แบบ: บทความปกติ (รูป/ข้อความ/ลิงก์) หรือ **iframe embed** (URL + ความสูง เอง) มีหน้า [youtube-embed.php](youtube-embed.php)/[feed-embed.php](feed-embed.php) เตรียมไว้ให้ใช้เป็น embed ได้ทันที (ไม่มี header/nav/footer ของเว็บปน)
- **ระบบสถิติ** — เก็บ pageview อัตโนมัติทั้งเว็บ (ไม่เก็บ IP ดิบ) แยกอุปกรณ์/ระบบปฏิบัติการ/บอท/ที่มา ดูภาพรวมพร้อมกราฟที่ [stats.php](stats.php) — มีช่องใส่โค้ด `<head>`/`</body>` เองได้ที่ [settings.php](settings.php) ด้วย เผื่ออยากต่อ Google Analytics/GTM ในอนาคต
- **ฟีดข่าวสั้น** ([feed.php](feed.php)) — ข่าว/ประกาศสั้นๆ (เช่นราคาหุ้น) แสดงแบบบอลลูนแชท เปิดหน้าค้างไว้แล้วข้อความใหม่ขึ้นเองอัตโนมัติ (poll ทุก 20 วิ) รับข้อมูลได้ทั้งพิมพ์เองที่ [manage-feed.php](manage-feed.php) (แก้ไข/ลบได้) และรับอัตโนมัติจาก pipeline ภายนอกผ่าน API (token แยกจากระบบนำเข้า Markdown)
- **หน้าแอดมิน** (ยังไม่มีระบบล็อกอินป้องกัน — เข้าได้ทุกคนตอนนี้ รอ Phase 3): [admin.php](admin.php) เป็น dashboard รวมลิงก์ไปหน้าจัดการทั้งหมดข้างต้น พร้อม sidebar เมนูถาวรทุกหน้าแอดมิน (คล้าย WordPress)

## เบื้องหลัง (ทำอะไรไปแล้วบ้าง กระชับๆ)

- **ฐานข้อมูล MySQL** (`mblog`) — บทความ/หน้า/รูป/หมวดหมู่/เมนู/redirect เก็บในตาราง `mblog_*` ทั้งหมดแล้ว (ย้ายออกจากไฟล์ json เดิมทั้งหมด) โครงสร้างตารางทุก Phase ดูได้ที่ `database/*.sql`
- **ชั้นข้อมูลกลาง** (`includes/*.php`) — หน้าเว็บไม่ยิง SQL เองตรงๆ เลย เรียกผ่านฟังก์ชันกลางเสมอ (`getArticles()`, `getPage()`, `getMenuItems()` ฯลฯ) วันหน้าเปลี่ยนแหล่งข้อมูลอีกครั้งจะแก้แค่ในฟังก์ชันเหล่านี้ ไม่ต้องแตะหน้าเว็บ
- **หน้ารายการทั้ง 5 หน้าใช้ query + partial กลางชุดเดียว** (`getArticleList()` ใน `includes/articles.php` ↔ `partials/article-list.php`) แทนที่จะแยกโค้ดคนละชุดต่อหน้า — แก้ดีไซน์การ์ด/pagination จุดเดียวมีผลกับทุกหน้าพร้อมกัน
- **`index.php` แค่ redirect (302 ชั่วคราว) ไป `articles.php`** — แยกหน้ารวมบทความออกจากหน้าแรกโดยเจตนา กัน "หน้าแรก" ในอนาคต (จะทำเป็นอย่างอื่น) พาโค้ดแสดงบทความหายไปด้วย
- **ระบบรูปภาพ** — อัปโหลดเก็บที่ `uploads/YYYY/MM/` ตั้งชื่อไฟล์คงชื่อเดิม (ดีต่อ SEO กว่าเดิมที่สุ่มชื่อ) ตาราง `mblog_images` รู้ว่ารูปไหนเป็นของบทความไหน sync ให้อัตโนมัติทุกครั้งที่บันทึก
- **Slug ปลอดภัยเพราะใช้ `id` เป็น primary key** ไม่ใช่ slug — แก้ URL ของบทความ/หน้าได้อิสระโดยไม่กระทบความสัมพันธ์ในฐานข้อมูล
- **สีของ badge หมวดหมู่เก็บเป็น "โทนสี" ไม่ใช่ hex ตรงๆ** — แมปกับคู่สีพื้นหลัง/ตัวอักษรที่เตรียมคอนทราสต์ไว้แล้วใน CSS กันเลือกสีแล้วอ่านยาก แต่ยังแก้ได้จาก DB โดยไม่ต้องแก้โค้ด
- **ค่าตั้งค่าเว็บรวมจุดเดียว** (ตาราง `mblog_settings`, แก้ผ่าน [settings.php](settings.php)) — ชื่อเว็บ, timezone, อีเมลเจ้าของ, ข้อความท้ายเว็บ แก้ที่เดียวจบ ไม่ต้องไล่หาในโค้ดหลายไฟล์ (เดิมเป็นไฟล์ `config/settings.php` ธรรมดา ย้ายเข้า DB ตอนทำหน้าแอดมินตั้งค่าจริง)
- **Post vs Page ใช้ตารางเดียวกัน** (`mblog_articles` + คอลัมน์ `type`) แทนแยกตาราง เพราะ field ที่ต้องใช้ร่วมกันเยอะ (slug, สถานะ, รูป, SEO) เหมือนแนวทางของ WordPress เอง
- **ธีมเว็บก็ยึดหลัก "แยกข้อมูลออกจากโค้ดที่แสดงผล" เหมือนกัน** — สีทุกจุดอ้างผ่าน CSS variable 2 ชั้นใน `assets/base.css` (สีดิบ → role token ที่ component เรียกใช้จริง) สลับทั้งเว็บจากสว่างเป็นมืดคือแก้บล็อกเดียว ไม่ต้องไล่แก้ไฟล์ CSS อื่น — สีที่ควรปรับตามแบรนด์องค์กรแยกออกจากสีระบบที่ล็อกไว้ตายตัวชัดเจน ดูรายการพร้อมจุดใช้งานได้ที่ [color-reference.php](color-reference.php), ดูตัวอย่างองค์ประกอบจริงที่ [theme-preview.php](theme-preview.php) และ**ปรับแต่ง/export/import ชุดสีเองได้จริง**พร้อมพรีวิวสดที่ [theme-editor.php](theme-editor.php) (ไม่ต้องแก้โค้ด เก็บแยกจาก `assets/base.css` เสมอ กด "คืนค่าเริ่มต้น" ได้ทุกเมื่อ)
- **Sidebar item ใช้ตารางแยก (`mblog_sidebar_items`) ไม่ยุบรวมกับบทความ** — ต่างจาก Page ที่ยุบรวมกับบทความในตารางเดียว (field ที่ใช้ร่วมกันเยอะ) sidebar item ไม่ใช่หน้าที่มี URL ของตัวเอง ไม่ต้องมี slug/SEO/tag/category/ถังขยะ เลยแยกตารางให้เบากว่าแทน — คนละสถานการณ์กัน แม้หลักการ "แยกข้อมูล-โค้ด" จะเหมือนกัน
- **สถิติไม่เก็บ IP ดิบเลย** — เก็บแค่ hash (ผสม salt ที่หมุนทุกวัน) พอให้นับ unique visitor ได้ โดยไม่แบกความเสี่ยงด้าน PDPA จากการเก็บ IP ตรงๆ ไว้
- **Sidebar เมนูแอดมินยืม layout engine เดิมของ sidebar เนื้อหาสาธารณะ** ไม่สร้าง CSS คู่ขนานใหม่ — ต่างแค่ override ตัวแปร CSS ตัวเดียว (`--sidebar-width`) ให้ค่าเริ่มต้นยังเหมือนเดิมทุกที่ที่ไม่ได้ override
- **ฟีดข่าวสั้นแยกตาราง (`mblog_feed_items`) ไม่ยุบรวมกับบทความ** เหตุผลเดียวกับ sidebar item — โครงสร้างต่างกันเกินไป (ไม่มี SEO/รูปปก/หมวดหมู่ ความถี่สูงกว่ามาก)
- **หน้าฟีดสด (`feed.php`) ให้เซิร์ฟเวอร์ render HTML ทั้งชุดใหม่ทุกครั้งที่ poll แทนการ query แค่ "อะไรใหม่"** — เรียบง่ายกว่าและได้ผลพลอยได้ฟรี: แก้ไข/ลบข้อความเก่า sync ไปหน้าที่เปิดค้างไว้ได้ทันที ไม่ต้องมีโค้ดแยกสำหรับกรณีนั้น
- **ไฟล์อัปโหลดที่ไม่ได้ใช้แล้วถูกลบจริง** (`includes/uploads.php`) เมื่อเปลี่ยน/ลบ featured image — เช็คก่อนเสมอว่าไม่มีบทความ/sidebar item อื่นยังอ้างถึงไฟล์เดิมอยู่ กันลบรูปที่ยังใช้อยู่จริงพลาด
- **header/sidebar/footer ประกอบหน้าผ่าน wrapper function จริง** (`render_header()`/`render_sidebar()`/`render_footer()` ใน `includes/layout.php`) แทนการ `include` ตรงๆ — เปิดไฟล์หน้าไหนก็เห็นทันทีว่าประกอบด้วยอะไรบ้าง ไม่ต้องเดา, เพิ่มส่วนใหม่ (เช่นเมนูซ้ายในอนาคต) แค่เพิ่มฟังก์ชันใหม่ 1 ตัวไม่กระทบของเดิม
- **การเทียบเวลา (ตั้งเวลาเผยแพร่/วันหมดอายุ) ไม่ใช้ cron เลย** — เทียบ `published_at`/`expires_at` กับเวลาปัจจุบันตอน query ตรงๆ ผ่านฟังก์ชันเดียว (`publicVisibilitySql()`) ครอบทุก query สาธารณะ — บทความที่ถึงเวลาจะขึ้นเองโดยไม่ต้องมีอะไรมา "flip" สถานะ

เหตุผลการตัดสินใจแต่ละจุด สถานะปัจจุบัน และแผนงานที่เหลือ ดูที่ [PLANNING.md](PLANNING.md) — รายละเอียดเชิงลึกระดับไฟล์/ฟังก์ชัน/บั๊กที่แก้แล้วของทุกฟีเจอร์ ดูที่ [BUILT.md](BUILT.md)

## ยังไม่มี

ล็อกอิน/สิทธิ์ผู้ใช้ (หน้าแอดมินทุกหน้าตอนนี้เข้าได้โดยไม่ต้องล็อกอิน — ยิ่งสำคัญขึ้นหลังเพิ่มช่องใส่โค้ด head/body เองได้), คอมเมนต์, cron/offsite copy อัตโนมัติสำหรับ backup — อยู่ในแผนแล้ว ดูรายละเอียดที่ [PLANNING.md](PLANNING.md)

## รันโปรเจกต์

1. สร้างฐานข้อมูล MySQL แล้วรันไฟล์ใน `database/` (เริ่มจาก `phase1_core.sql` ก่อนเสมอ ไฟล์อื่นรันเพิ่มทีหลังตามต้องการ รวม `settings.sql` สำหรับค่าตั้งค่าเว็บ)
2. คัดลอก `config.example.php` เป็น `config.php` แล้วปรับค่า DB ตามเครื่อง (`config.php` ไม่ถูก commit เข้า git) — ค่าตั้งค่าเว็บอื่นๆ (ชื่อเว็บ/timezone ฯลฯ) แก้ทีหลังผ่านหน้า `settings.php` ได้เลย ไม่ต้องแก้ไฟล์
3. ใช้ PHP + Apache (เช่น XAMPP) ชี้ document root มาที่โฟลเดอร์นี้ แล้วเปิด `index.php` (จะพาไปหน้ารวมบทความอัตโนมัติ)
