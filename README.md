# mBlog

เว็บบล็อกที่สร้างเองด้วย PHP + MySQL ล้วนๆ (ไม่ใช้ WordPress) กำลังพัฒนาแบบเริ่มจากส่วนเล็กๆ ก่อน ดูแผนงานทั้งหมดได้ที่ [PLANNING.md](PLANNING.md)

## ตอนนี้ทำอะไรได้แล้ว

ระบบเขียนบทความแบบ WYSIWYG พร้อม **ฐานข้อมูล MySQL เต็มระบบแล้ว**:

- เขียน/แก้ไข/อ่านบทความ ([editor.php](editor.php), [article.php](article.php), [articles.php](articles.php) — หน้ารวมบทความทั้งหมด) และ **หน้าเดี่ยว (Page)** เช่น เกี่ยวกับเรา/ติดต่อเรา/นโยบายความเป็นส่วนตัว ([page.php](page.php), [pages.php](pages.php) — หน้ารวม Page ทั้งหมด) — สลับประเภทได้ในตัวเขียน
- **หน้ารวมบทความตามหมวดหมู่** ([category.php](category.php)) และ**ตามแท็ก** ([tag.php](tag.php)) อัปเดตอัตโนมัติเมื่อมีบทความใหม่เข้าหมวด/แท็ก ไม่ต้องแก้เมนูเอง — หน้ารวมทั้ง 5 แบบ (บทความ/หน้า/หมวดหมู่/แท็ก/ร่าง) มี **pagination ครบทุกหน้าแล้ว** (จำนวนต่อหน้าตั้งค่าได้ที่ [settings.php](settings.php)) พร้อมพรีวิวพารากราฟแรกของเนื้อหาใต้วันที่ (สูงสุด 500 ตัวอักษร กันการ์ดล้น)
- จัดฟอร์แมตข้อความ: หัวข้อ H1–H3, ตัวหนา/เอียง/ขีดเส้นใต้, สีตัวอักษร, จัดกึ่งกลาง/ซ้าย/ขวา, bullet/numbered list
- แทรกรูปภาพ พร้อมลากปรับขนาด, จัดตำแหน่งซ้าย/กลาง/ขวา, ใส่คำบรรยายใต้ภาพ
- ใส่ลิงก์ได้ทั้งบนข้อความและบนรูปภาพ + auto-link (พิมพ์/วาง URL แล้วกลายเป็นลิงก์ให้เอง)
- Blockquote, code block พร้อม syntax highlighting (สไตล์ GitHub) และปุ่มคัดลอกโค้ด
- เส้นคั่นบทความ
- รองรับมือถือ (responsive)
- ระบบร่าง/เผยแพร่ (draft/published) แยกปุ่ม "บันทึกร่าง"/"เผยแพร่" ในตัวเขียน พร้อมหน้ารายการร่าง ([drafts.php](drafts.php))
- **แก้ slug เองได้** (ไม่กรอกจะสร้างจากชื่ออัตโนมัติ) พร้อม **301 redirect อัตโนมัติ** เมื่อ slug เปลี่ยน กันลิงก์เก่าที่แชร์ไปแล้วใช้ไม่ได้
- หมวดหมู่แบบ dropdown (เฉพาะบทความ — หน้าเดี่ยวไม่มีหมวดหมู่, **ไม่บังคับเลือกด้วย** ค่าเริ่มต้นคือ "ไม่ระบุหมวดหมู่") พร้อม **badge สีต่างกันตามหมวด** (คลิกไปหน้ารวมของหมวดนั้นได้เลย — ไม่มีหมวดก็ไม่มี badge)
- **แท็กแบบ freeform** — ช่อง chip input + autocomplete ในตัวเขียน พิมพ์แล้ว Enter เพื่อสร้าง/เลือกแท็กที่มีอยู่แล้วก็ได้ (many-to-many ต่างจากหมวดหมู่ที่มีได้แค่อันเดียว) พร้อมหน้ารวมบทความตามแท็ก ([tag.php](tag.php))
- **เวลาบทความแบบ Facebook** — โชว์เป็น "5 นาที"/"2 ชั่วโมง"/"3 วัน" แล้วเปลี่ยนเป็นวันที่เต็มหลัง 7 วัน เอาเมาส์ไปวางเห็นวันที่/เวลาเต็มเสมอ (อิงเขตเวลาจากค่าตั้งค่าเว็บ)
- เมนูเว็บปรับแต่งได้ รองรับเมนูย่อย — desktop เปิดด้วย hover แบบ WordPress (ตัวคำหลักคลิกไปหน้านั้นได้จริง), มือถือเป็น hamburger + accordion เต็มความกว้าง
- SEO พื้นฐาน: สรุปสั้น (excerpt) + featured image (อัปโหลดเองหรือใช้รูปแรกในเนื้อหาอัตโนมัติ), meta description, Open Graph/Twitter Card, canonical tag, JSON-LD, [sitemap.php](sitemap.php), [robots.txt](robots.txt)
- หน้า error กลาง (404/500) ที่หน้าตาเข้ากับเว็บ + log ข้อผิดพลาดลงไฟล์ + สคริปต์ backup ไฟล์ พร้อม retention ([scripts/backup.php](scripts/backup.php)) — **หมายเหตุ:** ยัง backup แค่ไฟล์ ไม่ได้ dump ฐานข้อมูลด้วย (งานค้าง)
- **ธีมเว็บสว่าง/มืดสลับได้** — ปุ่ม toggle มุมขวาบนทุกหน้า จำค่าไว้ที่เครื่องผู้อ่าน (ไม่ใช่ค่ากลางของเว็บ) ดีไซน์ cream + coral + dark navy ตาม `claude-design.md` — header แยก 2 แถว (โลโก้/ชื่อเว็บ กับ เมนูพื้นหลังส้ม coral เด่นชัด), แจ้งเตือนสำเร็จ/ผิดพลาดเป็น toast ลอยกลางจอ
- **แบรนด์เว็บ** — ตั้งโลโก้ + favicon + สโลแกน (เปิด/ปิดแยกจากข้อความ) ได้ที่ [settings.php](settings.php) โลโก้โชว์หน้าชื่อเว็บใน header เสมอ
- **Sidebar** — แบนเนอร์/ประกาศ/ป้ายโฆษณา/ป้ายลิงก์ ข้างเนื้อหา (เลือกซ้าย/ขวาได้ที่ตั้งค่าเว็บ) จัดการได้เต็มรูปแบบที่ [sidebar-items.php](sidebar-items.php) (เพิ่ม/แก้ผ่าน [sidebar-item-editor.php](sidebar-item-editor.php) ด้วย Quill editor เต็มรูปแบบ, สลับแสดง/ซ่อนและจัดลำดับได้) ไม่มีรายการที่เปิดใช้งานก็ไม่มี sidebar โผล่มาเลย
- **หน้าแอดมิน** (ยังไม่มีระบบล็อกอินป้องกัน — เข้าได้ทุกคนตอนนี้ รอ Phase 3): [admin.php](admin.php) เป็น dashboard รวมลิงก์ + จำนวนคร่าวๆ ของทุกหน้าด้านล่าง — [settings.php](settings.php) ตั้งค่าเว็บ, [menu.php](menu.php) จัดการเมนู, [categories.php](categories.php) จัดการหมวดหมู่ (ลบหมวดไม่ทำลายบทความ แค่ทำให้บทความไม่มีหมวดหมู่), [sidebar-items.php](sidebar-items.php) จัดการ sidebar

## เบื้องหลัง (ทำอะไรไปแล้วบ้าง กระชับๆ)

- **ฐานข้อมูล MySQL** (`mblog`) — บทความ/หน้า/รูป/หมวดหมู่/เมนู/redirect เก็บในตาราง `mblog_*` ทั้งหมดแล้ว (ย้ายออกจากไฟล์ json เดิมทั้งหมด) โครงสร้างตารางทุก Phase ดูได้ที่ `database/*.sql`
- **ชั้นข้อมูลกลาง** (`includes/*.php`) — หน้าเว็บไม่ยิง SQL เองตรงๆ เลย เรียกผ่านฟังก์ชันกลางเสมอ (`getArticles()`, `getPage()`, `getMenuItems()` ฯลฯ) วันหน้าเปลี่ยนแหล่งข้อมูลอีกครั้งจะแก้แค่ในฟังก์ชันเหล่านี้ ไม่ต้องแตะหน้าเว็บ
- **หน้ารายการทั้ง 5 หน้าใช้ query + partial กลางชุดเดียว** (`getArticleList()` ใน `includes/articles.php` ↔ `partials/article-list.php`) แทนที่จะแยกโค้ดคนละชุดต่อหน้า — แก้ดีไซน์การ์ด/pagination จุดเดียวมีผลกับทุกหน้าพร้อมกัน
- **`index.php` แค่ redirect (302 ชั่วคราว) ไป `articles.php`** — แยกหน้ารวมบทความออกจากหน้าแรกโดยเจตนา กัน "หน้าแรก" ในอนาคต (จะทำเป็นอย่างอื่น) พาโค้ดแสดงบทความหายไปด้วย
- **ระบบรูปภาพ** — อัปโหลดเก็บที่ `uploads/YYYY/MM/` ตั้งชื่อไฟล์คงชื่อเดิม (ดีต่อ SEO กว่าเดิมที่สุ่มชื่อ) ตาราง `mblog_images` รู้ว่ารูปไหนเป็นของบทความไหน sync ให้อัตโนมัติทุกครั้งที่บันทึก
- **Slug ปลอดภัยเพราะใช้ `id` เป็น primary key** ไม่ใช่ slug — แก้ URL ของบทความ/หน้าได้อิสระโดยไม่กระทบความสัมพันธ์ในฐานข้อมูล
- **สีของ badge หมวดหมู่เก็บเป็น "โทนสี" ไม่ใช่ hex ตรงๆ** — แมปกับคู่สีพื้นหลัง/ตัวอักษรที่เตรียมคอนทราสต์ไว้แล้วใน CSS กันเลือกสีแล้วอ่านยาก แต่ยังแก้ได้จาก DB โดยไม่ต้องแก้โค้ด
- **ค่าตั้งค่าเว็บรวมจุดเดียว** (ตาราง `mblog_settings`, แก้ผ่าน [settings.php](settings.php)) — ชื่อเว็บ, timezone, อีเมลเจ้าของ, ข้อความท้ายเว็บ แก้ที่เดียวจบ ไม่ต้องไล่หาในโค้ดหลายไฟล์ (เดิมเป็นไฟล์ `config/settings.php` ธรรมดา ย้ายเข้า DB ตอนทำหน้าแอดมินตั้งค่าจริง)
- **Post vs Page ใช้ตารางเดียวกัน** (`mblog_articles` + คอลัมน์ `type`) แทนแยกตาราง เพราะ field ที่ต้องใช้ร่วมกันเยอะ (slug, สถานะ, รูป, SEO) เหมือนแนวทางของ WordPress เอง
- **ธีมเว็บก็ยึดหลัก "แยกข้อมูลออกจากโค้ดที่แสดงผล" เหมือนกัน** — สีทุกจุดอ้างผ่าน CSS variable 2 ชั้นใน `assets/base.css` (สีดิบ → role token ที่ component เรียกใช้จริง) สลับทั้งเว็บจากสว่างเป็นมืดคือแก้บล็อกเดียว ไม่ต้องไล่แก้ไฟล์ CSS อื่น
- **Sidebar item ใช้ตารางแยก (`mblog_sidebar_items`) ไม่ยุบรวมกับบทความ** — ต่างจาก Page ที่ยุบรวมกับบทความในตารางเดียว (field ที่ใช้ร่วมกันเยอะ) sidebar item ไม่ใช่หน้าที่มี URL ของตัวเอง ไม่ต้องมี slug/SEO/tag/category/ถังขยะ เลยแยกตารางให้เบากว่าแทน — คนละสถานการณ์กัน แม้หลักการ "แยกข้อมูล-โค้ด" จะเหมือนกัน

รายละเอียดเชิงลึก เหตุผลการตัดสินใจแต่ละจุด และแผนงานที่เหลือ ดูที่ [PLANNING.md](PLANNING.md)

## ยังไม่มี

ล็อกอิน/สิทธิ์ผู้ใช้ (หน้าแอดมินทุกหน้าตอนนี้เข้าได้โดยไม่ต้องล็อกอิน), คอมเมนต์, ค้นหา, สถิติ, backup ที่ครอบคลุมฐานข้อมูล — อยู่ในแผนแล้ว ดูรายละเอียดที่ [PLANNING.md](PLANNING.md)

## รันโปรเจกต์

1. สร้างฐานข้อมูล MySQL แล้วรันไฟล์ใน `database/` (เริ่มจาก `phase1_core.sql` ก่อนเสมอ ไฟล์อื่นรันเพิ่มทีหลังตามต้องการ รวม `settings.sql` สำหรับค่าตั้งค่าเว็บ)
2. คัดลอก `config.example.php` เป็น `config.php` แล้วปรับค่า DB ตามเครื่อง (`config.php` ไม่ถูก commit เข้า git) — ค่าตั้งค่าเว็บอื่นๆ (ชื่อเว็บ/timezone ฯลฯ) แก้ทีหลังผ่านหน้า `settings.php` ได้เลย ไม่ต้องแก้ไฟล์
3. ใช้ PHP + Apache (เช่น XAMPP) ชี้ document root มาที่โฟลเดอร์นี้ แล้วเปิด `index.php` (จะพาไปหน้ารวมบทความอัตโนมัติ)
